## ১. সফটওয়্যারটি কী দিয়ে তৈরি

| অংশ | কী কাজ করে |
|---|---|
| **React + Vite** | ওয়েবসাইটের পাতা ও অ্যাডমিন ড্যাশবোর্ড (`src` ফোল্ডার) |
| **Supabase** | ডাটাবেস, লগইন আর ছবি রাখার জায়গা (storage) |
| **GitHub** (`rbchy/dhoom-vivekananda-samiti`, private) | কোডের ব্যাকআপ ও সংস্করণের ইতিহাস |
| **Capacitor** | একই সাইট থেকে Android / iOS অ্যাপ |

ওয়েবসাইটের দুটো অংশ:
- **সাধারণ সাইট** (`/`) — দর্শনার্থীদের জন্য: প্রতিষ্ঠান, পূজার সময়সূচি, অনুষ্ঠান, গ্যালারি, দান, যোগাযোগ। ১০টি ভাষা।
- **অ্যাডমিন প্যানেল** (`/admin/login`) — কমিটির কর্মীদের জন্য।

## ৩. প্রথমবার ইনস্টল করা

### ৩.১ কোড নামানো
নতুন কম্পিউটারে:
```bash
cd ~/eclipse-workspace-Rbc
git clone https://github.com/rbchy/dhoom-vivekananda-samiti.git Dhoom-Vivekananda-Samitee
cd Dhoom-Vivekananda-Samitee
```

### ৩.২ প্যাকেজ বসানো
```bash
npm install
```
প্রথমবার কয়েক মিনিট লাগতে পারে। এতে `node_modules` ফোল্ডার তৈরি হবে।

### ৩.৩ গোপন সেটিংস (`.env` ফাইল)
`.env.example` কপি করে `.env` নামে রাখুন:
```bash
cp .env.example .env
```
তারপর `.env` খুলে মানগুলো বসান:

| নাম | কী বসাবেন | কোথায় পাবেন |
|---|---|---|
| `VITE_SUPABASE_URL` | প্রজেক্টের ঠিকানা (`https://….supabase.co`) | Supabase → Project Settings → API |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Publishable (anon) key | Supabase → Project Settings → API Keys |
| `VITE_DONATION_BKASH` / `NAGAD` / `ROCKET` | কমিটি-অনুমোদিত নম্বর | কমিটি |
| `VITE_DONATION_BANK` | ব্যাংকের বিবরণ | কমিটি |
| `VITE_DONATION_PAYMENT_URL` | কার্ড পেমেন্ট লিংক (Stripe / SSLCommerz) — না থাকলে খালি | পেমেন্ট সেবা |
| `VITE_SITE_URL` | সাইটের আসল ঠিকানা, যেমন `https://dhoomvivekanandasamiti.org` | ডোমেইন কেনার পর |

> ⚠️ **কখনো `service_role` বা secret key `.env`-এ বসাবেন না।** শুধু publishable key। `.env` ফাইল GitHub-এ যায় না (`.gitignore`-এ আটকানো)।

খালি রাখা দানের ঘর ওয়েবসাইটে দেখাবে না।

## ৪. ডাটাবেস সেটআপ (Supabase)

সব SQL ফাইল `supabase` ফোল্ডারে। চালানোর নিয়ম: **Supabase Dashboard → SQL Editor → New query → ফাইলের লেখা পেস্ট → Run**। প্রতিটি ফাইল একাধিকবার চালালেও ক্ষতি নেই।

### ৪.১ চালানোর ক্রম (নতুন প্রজেক্টে)

| ক্রম | ফাইল | কী করে |
|---|---|---|
| ১ | `donations-and-events-schema.sql` | অ্যাডমিন যাচাইয়ের ফাংশন, বার্ষিক অনুষ্ঠান-তালিকা, দান, মাসিক চাঁদা |
| ২ | `temple-management-schema.sql` | পূজার সময়সূচি, মন্দিরের তথ্য, কমিটি, বার্তা, আয়, ব্যয় |
| ৩ | `site-extras-schema.sql` | ব্যানারের লেখা, লক্ষ্য ও দেবদেবী, হিসাবের খাত |
| ৪ | `organisations-gallery-schema.sql` | গ্যালারির ছবি কোন প্রতিষ্ঠানের, সেই ঘর |
| ৫ | `storage-photos-policy.sql` | ছবি রাখার জায়গা (`event-photos`) |
| ৬ | `security-hardening.sql` | নিরাপত্তা শক্ত করা |
| ৭ | `roles-and-approvals.sql` | তিন ভূমিকা ও অনুমোদন-ব্যবস্থা |

> ℹ️ `events`, `gallery`, `announcements`, `temple_content` আর `admin_profiles` টেবিল আগে Supabase ড্যাশবোর্ড থেকে সরাসরি বানানো হয়েছিল — এগুলোর SQL ফাইল রিপোতে নেই। নতুন প্রজেক্টে বসাতে হলে আগে এগুলো বানাতে হবে।

### ৪.২ পরীক্ষার তথ্য (ঐচ্ছিক)
- `test-data-seed.sql` — প্রতিটি টেবিলে ১০টি নমুনা সারি (নকল ফোন ৫৫৫-০১xx, example.com ইমেইল)।
- `remove-test-data.sql` — শুধু নমুনা সারিগুলো মুছে দেয়, আসল তথ্যে হাত দেয় না।

> ⚠️ সাইট চালু করার আগে অবশ্যই `remove-test-data.sql` চালান।

### ৪.৩ নিরাপত্তা পরীক্ষা
`security-audit.sql` কিছু বদলায় না, শুধু দেখায়। SQL Editor একসঙ্গে পুরো ফাইল চালালে শুধু **শেষ অংশের** ফলাফল দেখায় — তাই প্রতিটি অংশ আলাদা সিলেক্ট করে Run দিন।

### ৪.৪ Supabase-এর অন্যান্য সেটিং
- **Authentication → Sign In / Providers → "Allow new users to sign up" বন্ধ রাখুন।** কর্মীদের লগইন শুধু অ্যাডমিন বানাবেন।
- **প্রথম প্রধান অ্যাডমিন** (একবারই, SQL Editor-এ — ইমেইল বদলে):
  ```sql
  insert into public.admin_profiles (user_id, role)
  select id, 'admin' from auth.users where email = 'name@example.com';
  ```
  এর আগে Authentication → Users → **Add user** দিয়ে লগইন বানাতে হবে। এরপর বাকি সবাইকে ড্যাশবোর্ডের **কর্মী ও ভূমিকা** পাতা থেকে যোগ করা যাবে।

## ৫. সাইট চালানো

### ৫.১ নিজের কম্পিউটারে (উন্নয়নের সময়)
```bash
npm run dev
```
- ব্রাউজারে খুলুন: `http://localhost:5173`
- অ্যাডমিন প্যানেল: `http://localhost:5173/admin/login`
- একই Wi-Fi-তে থাকা ফোন থেকে দেখতে: পাতার **QR কোড** বোতাম স্ক্যান করুন।
- বন্ধ করতে Terminal-এ **Control + C**।

### ৫.২ চূড়ান্ত সংস্করণ তৈরি (production build)
```bash
npm run build      # dist ফোল্ডারে চূড়ান্ত ফাইল তৈরি হয়
npm run preview    # তৈরি হওয়া সংস্করণটি নিজের কম্পিউটারে দেখা
```
অনলাইনে তোলার সময় শুধু `dist` ফোল্ডারটাই হোস্টিংয়ে যায় (Vercel / Netlify নিজেরাই `npm run build` চালায়)।

> হোস্টিংয়ে `.env`-এর মানগুলো আলাদা করে **Environment Variables** হিসেবে বসাতে হবে — `.env` ফাইল সেখানে যায় না।

## ৬. কর্মী, ভূমিকা ও অনুমোদন

### ৬.১ তিনটি ভূমিকা

| ভূমিকা | যা করতে পারেন | যা অনুমোদন করেন |
|---|---|---|
| **প্রধান অ্যাডমিন** (`admin`) | ওয়েবসাইটের সব কনটেন্ট সরাসরি বদলানো; হিসাব **শুধু দেখা**; বার্তা পড়া; কর্মীদের ভূমিকা দেওয়া | সম্পাদকের **কনটেন্ট** অনুরোধ |
| **হিসাব অ্যাডমিন** (`accounts_admin`) | দান, মাসিক চাঁদা, আয়, ব্যয়, হিসাবের খাত সরাসরি লেখা — নিজের এন্ট্রিতে অনুমোদন লাগে না | সম্পাদকের **হিসাবের** অনুরোধ |
| **সম্পাদক** (`secretary`) | কনটেন্ট ও হিসাব — দুটোতেই যোগ / সম্পাদনা / মুছে ফেলার **অনুরোধ** পাঠানো | — |

### ৬.২ কাজের ধারা
1. সম্পাদক কোনো পাতায় "সংরক্ষণ" বা "মুছুন" চাপলে পরিবর্তন সরাসরি হয় না — অনুরোধ হিসেবে জমা হয়। নিচে লেখা ভেসে ওঠে: *"অনুমোদনের জন্য পাঠানো হয়েছে"*।
2. অনুরোধ নিজে থেকেই ঠিক জনের কাছে যায় — কনটেন্ট → প্রধান অ্যাডমিন, হিসাব → হিসাব অ্যাডমিন।
3. অ্যাডমিন **✅ অনুমোদন** পাতায় "Details" চেপে আগে-পরে তুলনা দেখেন, তারপর **অনুমোদন** (সঙ্গে সঙ্গে চালু) বা **বাতিল** (কারণ লেখা বাধ্যতামূলক)।
4. সম্পাদক **📨 আমার অনুরোধ** পাতায় ফলাফল ও অ্যাডমিনের মন্তব্য দেখেন; অপেক্ষমাণ অনুরোধ প্রত্যাহারও করতে পারেন।

**নিয়ম:** কেউ নিজের অনুরোধ নিজে অনুমোদন করতে পারেন না। হিসাব অ্যাডমিন কনটেন্ট অনুমোদন করতে পারেন না, প্রধান অ্যাডমিন হিসাব অনুমোদন করতে পারেন না। প্রতিটি সিদ্ধান্তের রেকর্ড থাকে।

### ৬.৩ নতুন কর্মী যোগ করা
1. Supabase → **Authentication → Users → Add user** (ইমেইল + পাসওয়ার্ড)।
2. প্রধান অ্যাডমিন হিসেবে লগইন → **👥 কর্মী ও ভূমিকা** → ইমেইল লিখে ভূমিকা বেছে **ভূমিকা দিন**।

### ৬.৪ কাউকে সরানো
**কর্মী ও ভূমিকা** পাতায় **Remove access**। তাঁর লগইন থেকে যায় কিন্তু প্যানেলে ঢুকতে পারেন না। পুরোপুরি মুছতে Supabase → Authentication → Users থেকে মুছুন।

> নিজের প্রধান-অ্যাডমিন অধিকার নিজে সরানো যায় না (ভুল করে সবাই আটকে না যাওয়ার জন্য)।

## ৮. কোড আপডেট ও GitHub

ফোল্ডারটি GitHub-এর সঙ্গে যুক্ত (`main` branch)।

|---|---|

## ১০. নিরাপত্তার নিয়ম

1. `.env` ফাইল কাউকে পাঠাবেন না, কোথাও আপলোড করবেন না।
2. Supabase-এর **service_role / secret key** কখনো সাইটের কোডে বা `.env`-এ নয়।
3. **supabase.com** ও **github.com** — দুই অ্যাকাউন্টেই দুই ধাপের যাচাই (2FA) চালু রাখুন।
4. Supabase-এ নতুন অ্যাকাউন্ট খোলা (sign up) বন্ধ রাখুন।
5. কাউকে প্রয়োজনের বেশি ভূমিকা দেবেন না। কেউ দায়িত্ব ছাড়লে সঙ্গে সঙ্গে প্রবেশাধিকার সরান।
6. দানের নম্বর শুধু কমিটি-অনুমোদিত হতে হবে।
7. ছবি শুধু সেগুলোই দেবেন যেগুলো প্রকাশের অনুমতি আছে। AI দিয়ে বানানো ছবি হলে নিচে উল্লেখ করুন।

## ১২. সমস্যা ও সমাধান

| সমস্যা | কারণ | সমাধান |
|---|---|---|
| সাইট খুললে সাদা পাতা, Console-এ *"Supabase URL or Publishable Key is missing"* | `.env` নেই বা মান খালি | ধাপ ৩.৩ অনুযায়ী `.env` বানান, তারপর `npm run dev` আবার চালান |
| `npm run dev` চালালে *"command not found: npm"* | Node.js বসানো নেই | nodejs.org থেকে বসান |
| লগইনে *"Email or password is incorrect"* | ভুল পাসওয়ার্ড | Supabase → Authentication → Users → ব্যবহারকারী → পাসওয়ার্ড রিসেট |
| লগইনে *"You are not authorized to use the admin panel"* | লগইন আছে কিন্তু ভূমিকা নেই | প্রধান অ্যাডমিন **কর্মী ও ভূমিকা** থেকে ভূমিকা দিন |
| সংরক্ষণে *"new row violates row-level security policy"* বা *"permission denied"* | এই কাজের অনুমতি এই ভূমিকার নেই (যেমন প্রধান অ্যাডমিন হিসাব বদলাতে চাইছেন) | ঠিক ভূমিকার জনকে দিয়ে করান, বা সম্পাদকের মাধ্যমে অনুরোধ |
| সম্পাদক কিছু মুছলেন কিন্তু পাতা আবার খুললে ফিরে এল | অনুমোদন এখনো হয়নি | স্বাভাবিক — অনুমোদনের পর মুছে যাবে |
| অনুমোদনে *"The row no longer exists"* | অনুরোধের পরে জিনিসটি অন্য কেউ মুছে ফেলেছেন | অনুরোধটি বাতিল করুন |
| ছবি আপলোডে ত্রুটি | ৫ MB-এর বেশি বা JPG/PNG/WebP নয় | ছোট করে বা ফরম্যাট বদলে আবার দিন |
| `git push`-এ *"rejected… fetch first"* | GitHub-এ নতুন বদল আছে যা কম্পিউটারে নেই | আগে `git pull`, তারপর `git push` |
| `npm run build`-এ *"/RamaKrishna-dhoomT.jpg didn't resolve"* সতর্কবার্তা | কোডে উল্লেখিত ছবিটি `public` ফোল্ডারে নেই | ছবিটি `public`-এ রাখুন বা কোড থেকে উল্লেখ সরান (build তবুও হয়) |

সমস্যার সময় ব্রাউজারে **Option + Command + J** (Mac) চেপে Console-এর লাল লেখার স্ক্রিনশট নিন — সমাধানে সাহায্য করবে।
